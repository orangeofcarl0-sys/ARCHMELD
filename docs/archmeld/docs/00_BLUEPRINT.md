# 产品与技术总览

## 1. 产品工作对象

ARCHMELD 维护的不是一张大图，而是三类版本化对象：**证据、理解/设计、变更/验证**。源码、符号索引、运行事件是证据；职责、所有权、状态机和假设是理解；目标架构、迁移步骤和验收记录是设计与变更。模型提出的判断不自动成为源码事实。

用户要能从一行代码到一次执行，从执行到机制，从机制到目标架构，再返回实现和验证。一次有价值的调查必须给出结论、证据、替代解释、未覆盖部分与下一步风险；逐文件摘要的堆积不算系统理解。

## 2. 首版的真实形态

交付物是一个本地核心程序、一份 VS Code/Code-OSS 兼容扩展、一个 CLI/MCP 入口、按需安装的语言/运行适配器、离线报告导出器。无需云账户、向量数据库或常驻 LLM。图谱、查阅与验证在无模型时仍可工作；自然语言架构推理通过可选模型或外部编码 Agent 提供。

Manager 和 Expedition 的模型与验证能力相同，区别仅为生命周期、存储位置和默认写权限，不能把 Expedition 做成缩水扫描器。

## 3. 已确定基础与技术栈

CodeGraph 固定源码作为宿主工程；现有 Rust 解析与图服务复用，VS Code 扩展从上游薄改。新增 `archmeld-core` 和 `archmeld-cli` Rust crate；核心使用 SQLite 事务、内容寻址对象库及本地 API。UI 用 TypeScript 和 Cytoscape.js 组件，不另造编辑器。独立语言工具和 Python 架构分析器通过有版本的进程适配协议调用。

不把 CodeGraph 的所有历史/内存/Pro 功能搬进来。图后端隔离运行、graph-only、无自动下载；SQLite 才是快照、证据、架构与变更的事实权威。后端 RocksDB 是可删后重建缓存，不参与完成状态判定。

基础项目来源与边界见 docs/01_FOUNDATIONS.md、research/SOURCES.md；这些工程能力是可复用起点，不是已在 ARCHMELD 实测的能力声明。

## 4. 核心闭环

1. 捕获项目快照与构建环境，明确索引包含/排除内容。
2. 使用现成解析器与语义工具生成带来源的结构，保留未解析边。
3. 围绕具体问题查代码、跟路径、运行场景并检验候选解释。
4. 将职责、数据所有权、状态机和约束保存为可修订的架构模型。
5. 在目标模型中定义变化，不通过拖节点直接改代码。
6. 冻结行为契约、风险及验证计划，产生有限范围变更。
7. 在暂存区实施、测试，经前置内容检查应用到用户目录；复查后才验收。
8. Manager 更新知识有效性；Expedition 导出可复核成果并清理暂存资源。

## 5. 不打折的含义

必须保留可靠性闭环：来源、版本、未知状态、真实 Runtime、受控变更、测试、恢复、双模式、跨语言能力验收。可以复用原生工具查看深度 Trace，可以按能力公开盲区，不要求首版自行实现全程序证明或每种语言的完整编译器分析。

内部 S1 可以先作为真实只读工作台使用，S2 添加 Runtime，S3 添加重构；只有全部 R1 门禁通过才发布首版完整产品。对外不将 S1 冒充最终 R1，也不把后续设计目标偷偷降格为“可选”。

## 6. 初始平台与语言

首版发布门禁：Windows 11 x64 与 Ubuntu 24.04 x64。Windows 原生为主要交互环境；SCIP-Clang 的官方预编译平台不含 Windows，必须用原生 clangd 精确能力或明确配置的 Linux worker/WSL 适配，不能写成一条跨平台通用安装命令。[SRC-SCIP-CLANG]

语言组：C/C++、Python、JS/TS、Java、C#、Go、Rust。每组至少有结构、已解析定义/引用、明确未解析状态、一次真实运行证据、一次受控跨文件变更与验证。不是承诺任意反射、宏、动态分派均精确可解。MATLAB/科学计算增强单列，不拿降级文本解析冒充正式语义支持。

## 7. 默认交互与所有权

默认一个仓库、一个普通 Git 分支、一个主 Agent、一个写入者。工作台不抢占用户编辑；用户在计划期间改文件会触发过期/冲突检查。自动修改在暂存区进行，写入原仓库由核心受控应用。无需多工作树，也不把多 Agent 辩论当质量来源。

工作台的项目管理对象是：机制地图、问题/假设、设计决策、证据有效性、已验证重构、风险与下一行动；不是再实现一套 Jira。长期维护功能必须减少重复理解，不通过保存大量模型废话实现“记忆”。
