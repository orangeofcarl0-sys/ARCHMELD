# START HERE — 本地构建入口

你收到的是 **build-ready spec pack**，不是待润色的提案。当前任务是按规格构建 ARCHMELD；先复用底座并验证能力，再逐步填充新增核心。

## 读取顺序

先读根目录 AGENTS.md → docs/00_BLUEPRINT.md → docs/01_FOUNDATIONS.md → docs/02_REUSE_AND_REPO_MAP.md → execution/FIRST_SESSION.md → execution/work-items.json。其后每执行一个任务，只加载该任务标记的 spec、契约和验收条目，不将整个包反复塞进上下文。

## 第一次会话要做的事

在用户批准的本地目录中创建工作仓库；克隆 CodeGraph 并核对固定 SHA；记录机器、工具链与网络条件；构建并运行相关上游测试；定位源码复用点；完成最小稀疏 ID、缓存隔离、无网络索引探测。随后立即推进第一条“真实仓库 → 固定快照 → 结构证据 → 源码导航”纵向切片。

这不是要求先做数周平台建设。B000—B005 完成的是可追溯底座和第一条真实路径；不先做登录、云部署、复杂调度、全语言 CFG、向量数据库或漂亮但脱离事实的图。

## 目录与目标仓库

初始化包保持只读，作为设计基线。工作仓库应为其**旁边的新目录**，不要克隆到真实被分析的用户项目中。首次下载命令见 execution/FIRST_SESSION.md。将本包的规格复制到工作仓库 `docs/archmeld/`，保留根目录入口指向它们；不得覆盖上游已有 AGENTS.md，必须审阅后合并适用约束并留存原版。

## 需要做决定时

已冻结项按 ADR 执行。只允许在实际兼容性或安全证据表明不可行时修改；写一条明确 ADR，说明原假设、复现实验、影响和最小替代，不重新开启工具海选。

网络不可用：记录 BLOCKED_EXTERNAL，先做不依赖网络的契约测试与实现。禁止编造“依赖已安装”。上游构建失败：缩小到失败包并定位，不能立刻退回正则伪索引或删除测试。

## 工作节奏

每个任务遵循：读目标与验收 → 实施 → 运行测试 → 保存命令与退出码 → 更新状态 → 继续下一个可执行任务。普通成功步骤不逐项向用户请求确认。涉及新增付费服务、上传源码、执行未授权脚本、真实硬件和破坏性动作才请求相应批准。

每轮会话结束必须更新 templates/PROGRESS.md 所定义的状态：当前提交、通过与未通过、实证阻碍、下一可执行任务。不得用“建议后续进行测试”替代已经授权且能够运行的测试。
