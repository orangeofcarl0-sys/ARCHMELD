# S01 · 产品范围、工作模式与用户旅程

状态：R1 规范。需求追溯以 acceptance/requirements.json 的 spec_id=S01 条目为准；实现任务以 execution/work-items.json 为准。

## 1. Manager：长期项目管理者

打开项目后提供最近认可的系统地图、当前索引状态、待验证假设、架构约束、已验收变更和证据过期提示。Watcher 只负责发现变化与安排刷新，不擅自运行构建、模型或改源码。默认只读计算可在资源预算内自动进行；执行测试、安装依赖、调用模型分别服从授权。

持久状态位于系统应用数据目录的项目空间；可版本化的架构契约允许经用户选择写入项目 `.archmeld/`。不要求为了使用工具先污染 Git。项目重命名/搬移时以绑定记录重新关联，不把绝对路径当永久 ID。多个项目绝不共用无命名空间的事实库。

项目首页包含：系统地图、关键运行场景、问题/假设、计划与验证、变更历史五项。保持轻量，不实现人员绩效、工时或云协作管理。

## 2. Expedition：一次性梳理与重构者

输入本地仓库或普通源码目录、一个目标问题、可选场景与权限配置。默认在应用缓存的 session 目录生成所有索引和报告，原仓库字节不变。不是强制 git clone 用户仓库；未使用 Git 的目录也可生成内容快照。

默认流程：inspect → static facts → targeted investigation → runtime import/run（经授权）→ architecture review → optional change plan → report。用户可止于只读梳理，也可完成受控重构，后者与 Manager 使用完全相同的变更与验收机制。

退出前必须导出 manifest、结论、架构模型、证据索引、覆盖缺口、计划、实际验证状态。源码片段和原始 Trace 默认不外带，用户可选择加入。清理只删除 session 拥有的缓存，不能删除输入目录和用户自己指定的导出目录。

## 3. 两模式转换

Expedition 可提升为 Manager：校验全部对象 hash，迁移对象及引用，保留项目身份、快照、来源、已批准契约；不重新调用模型生成“相似报告”。原 session 在迁移事务完成后可清理，失败则仍可读取原数据。

Manager 可导出离线 review bundle：包含指定版本而非“当前目录随便一份”；阅读者可检查证据引用与产物完整性。打开报告不执行其中代码，不注册原仓库脚本。

## 4. 任务与会话恢复

任务状态属于核心，不属于聊天窗口。关闭 IDE 后可重新打开任务；正在运行的受管理进程按用户选择终止或明确保持，不能在 UI 消失时悄悄失控。进程 PID 与启动 token、工具版本、工作目录一并保存，不能只凭 PID 杀进程。

任务中断时保留最后一致快照、日志和产物；模型上下文可重新构建，但不把对话原文当唯一恢复依据。一次性 session 意外退出后通过恢复列表找回，不默认为成功清理。

## 5. 权限默认值

只读结构分析默认可用；语义工具若可能执行项目配置/构建必须经信任策略；测试/运行需要明确 runnable scenario；修改源代码需要已批准 ChangeSet；调用模型需 provider 与数据出站授权。模式本身不改变安全强度。

## 6. 完成标准

只读梳理完成：问题有结论或清晰未知，所有关键结论有证据或推断标签，相关场景覆盖情况明确，报告可重开。重构完成：代码已应用、契约通过、架构约束符合、性能/领域要求验证完成、恢复信息齐全。任何 required 检查未运行都阻止 accepted。
