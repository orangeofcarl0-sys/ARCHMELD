# Upstream integration and update policy

Status: U0/U1 governance, 2026-11-25.

This document describes how ARCHMELD consumes other projects. It is deliberately
not a "universal compatibility layer": each upstream has the boundary its failure
mode needs.

## Three layers

```text
L2  ARCHMELD private domain (archmeld-core, archmeld-api)
      no codegraph-* dependency; consumes EvidenceBatch / NDJSON only
              ^
              | versioned contract
L1  boundary contracts
      archmeld-export-v1 (NDJSON), analysis.json, SCIP, LSP, traces, AOCI
              ^
              | pin + adapter
L0  upstream source and tools
      CodeGraph thin fork, CodeBoarding, SCIP indexers, language servers,
      trace tools, toolchains
```

The dependency rule is one-way: L2 never imports L0. `archmeld-core/Cargo.toml`
has no `codegraph-*` dependency, and `tooling/upstream.py verify` checks the
resolved dependency closure.

## Source of truth

`upstreams.lock.json` at the repository root is the single registry. It records:

- reuse mode (`thin_fork`, `artifact_import`, `process_adapter`, `text_interop`,
  `vendored_asset`, `environment_pin`);
- pin (commit, lockfile, or version), observed upstream version and record;
- contract id/version and producer/consumer paths;
- update policy with `auto_follow`, `auto_merge`, `auto_pin_update` all false;
- last drill and evidence;
- the files that copy the pin (`pin_records`).

Derived or historical records are not rewritten by the registry:

- `toolchains.lock.json`, `AGENTS.md`, `UPSTREAM_PATCHES.md`,
  `third_party/NOTICE.md` are checked against the registry;
- `dist/release-manifest.json` is generated by `tooling/package_release.py`;
- `docs/archmeld/research/upstream-selection.json` is a sealed historical record
  (`docs/archmeld/` is a specification pack with `PACK_MANIFEST.json` and
  `SHA256SUMS`). Do not edit it without re-sealing the pack.
- Known pre-existing drift (2026-11-25): `verify` reports SHA256SUMS mismatches
  for `contracts/mcp-tools.json`, `contracts/schemas/archmeld.schema.json` and
  `specs/S11_API_MCP_EVENTS.md`. `git status -- docs/archmeld` is clean, so this
  predates U0/U1; it needs a separate re-seal task. Do not hand-edit the pack.

## Commands

```text
python tooling/upstream.py status [--json] [--remote]
python tooling/upstream.py verify [--json] [--out PATH] [--skip-cargo]
python tooling/upstream.py check codegraph [--json] [--fail-on-update]
```

- `status` is offline by default. `--remote` runs `git ls-remote` and is still
  read-only.
- `verify` checks registry schema, pin copies, generated-artifact drift,
  sealed-pack cleanliness, the export contract document, and the private core's
  dependency closure. It writes nothing unless `--out` is passed.
- `check` compares the registry pin with `git ls-remote`. It never fetches,
  merges, pushes or updates a pin. `--fail-on-update` returns exit code 3 when a
  newer commit exists.

U1 adds `patches`, `diff`, `drill` and `record`; those are still development-side
commands. They must never auto-merge or auto-change a pin.

## Update policy by upstream

| Upstream | Boundary | Update action |
|---|---|---|
| CodeGraph | thin fork + `archmeld-export-v1` | `check` → `diff` → `drill` in a temp worktree → tests → `record` (manual). |
| CodeBoarding | `analysis.json` artifact | Regenerate with the pinned commit, run importer contract tests. |
| SCIP | `.scip` protobuf | Regenerate fixture with pinned indexers, run decoder tests. |
| LSP servers | stdio JSON-RPC | Version probe, capability profile, real session audit. |
| Perfetto/Tracy/VizTracer | trace artifact | Regenerate fixture, record loss/coverage. |
| AOCI-CODE | read-only text | Tolerance fixture; malformed lines are warnings, not crashes. |
| Cytoscape.js | vendored asset | Manual vendor with license and hash. |
| Toolchain | environment pin | Relock and run `doctor.py`. |

Only CodeGraph can fail at compile time. The other boundaries fail at parse or
protocol time and are covered by fixtures.

## CodeGraph patch surface

`patches/codegraph/manifest.json` (U1) is a **path-level audit manifest**, not a
rebased patch series. The fork history currently contains many mixed commits, so
`git format-patch`/`git range-diff` are not useful yet. The manifest records every
modified upstream file, every new file inside an upstream tree, its necessity,
whether it is a candidate for upstream, and a diff digest. `patches --check`
fails when a changed upstream path is unaccounted for.

## Evidence

Every automated command must record cwd, argv, exit code, tool versions, log
hashes, artifact hashes and sandbox/trust state. Put committed logs under
`docs/evidence/upstream-<date>/`, structured records under
`docs/release-evidence/`, and append command records through
`python baseline/run_cmd.py`.
