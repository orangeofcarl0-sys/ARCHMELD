# Upstream registry and export provenance (2026-11-25)

Scope: U0/U1 governance for the CodeGraph fork and the other upstream
integrations. No pin was changed, no merge was performed, no source was uploaded,
and the sealed `docs/archmeld/` pack was not edited.

## What changed

- `upstreams.lock.json`: single registry for CodeGraph, CodeBoarding, SCIP, LSP,
  traces, AOCI, Cytoscape and the toolchain; every update policy disables
  auto-follow, auto-merge and auto-pin.
- `tooling/upstream.py`: read-only `status`/`verify`/`check`, plus U1
  `patches`/`diff`/`drill`/`record`.
- `archmeld-export-v1` manifest: additive `schema_version: "1.1"`,
  `producer_commit` and `producer_dirty`; `format` is unchanged.
- `bridge.rs`: accepts legacy `1.0`, accepts `1.x`, rejects another major,
  validates commit shape, and reports producer provenance.
- `patches/codegraph/manifest.json`: every changed upstream path is accounted
  for (18 paths, 10 entries), with path-scoped diff hashes and conflict
  hotspots.
- Stale tooling literals were removed: the old `590c2ca` pin and
  `AT077 partial` no longer appear in executable tooling.

## Boundaries

- `docs/archmeld/**` remains a sealed specification pack; the research record
  `upstream-selection.json` is reported as historical, not drift.
- `verify` reports a pre-existing sealed-pack drift: `SHA256SUMS` disagrees with
  HEAD bytes for `contracts/mcp-tools.json`,
  `contracts/schemas/archmeld.schema.json` and `specs/S11_API_MCP_EVENTS.md`.
  `git status -- docs/archmeld` is clean, so this predates this slice; it needs a
  separate re-seal task and was not edited here.
- `producer_commit` is visible in the export artifact, `BridgeReport` and the
  `archmeld index` summary. It is not yet a field of the core `Producer`
  evidence record because that schema is inside the sealed pack. A future
  contract revision must re-seal the pack.
- The patch manifest is a path-level audit, not a rebased series.
  `git format-patch`/`git range-diff` remain deferred.
- No real pin update was recorded; `record` was exercised only through the
  planner/dry-run tests.
